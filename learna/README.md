# Learna

Structured, course-aware learning inside Cognita. Route: `/app.html?view=learna`
(`&course=<id>` for a course page, `&lesson=<key>` for the workspace).

## Rules that matter

- **Access.** Any signed-in user can browse. Starting a course needs a plan with `learnaCourses > 0` (Plus 2, Studio and Admin unlimited).
- **Course limit.** Each active course on a limited plan holds a `learna_slots/{uid}_{n}` document created with `fsCreate`.
- **No answers in the browser.** Answer keys, accepted answers, rubric exemplars, hidden test cases and every expected value stay on the server.
- **Progress.** Advancing is validated against the stored position. A lesson is mastered at 70% of graded activities passed without the answer shown (an assessment lesson has its own threshold). Speaking practice is not graded and never blocks.
- **Versions.** In the admin editor you never set `rev` by hand. On publish, every lesson whose content changed gets `rev + 1` and the course version goes up, so learners repeat only what changed.
- **Tutor.** Built from stored state: course, section, lesson, objective, steps taught, attempts, mistakes, weak lessons, tasks waiting for review, and what comes next. It gets an answer only after the learner has been shown it, and it cannot mark work.

## Code grading trust

A Cloudflare Worker cannot run learner JavaScript, so the server cannot prove the browser really ran the code. Nothing here pretends otherwise.
What is done instead:

1. **One-time challenge.** Before each run the browser asks `POST /code/challenge`. The server picks two hidden cases at random from the task's pool and stores the nonce. The result is only accepted with that nonce, within 15 minutes, once.
2. **Expected values never leave the server.** To fake a passing report you would have to know the right answer for cases you have not seen, which means solving the task.
3. **Source is kept and scanned.** The passing source is stored (`learna_code_attempts`). If it holds several expected outputs as literals, the task is flagged and blocks the certificate until cleared.
4. **Independent re-run.** `scripts/verify-code-submissions.mjs` downloads passing submissions with all tests and expectations, runs them on a machine you control, and reports `verified` or `mismatch`. A mismatch sends the task back to the learner and blocks the certificate.
5. **People review the capstone.** The JavaScript certificate requires a reviewer to approve the capstone program.

What is still true: a learner who solves the task somewhere else and pastes the answer can pass the per-lesson task. That is solving the task, and the capstone review covers it. True proof of execution at the moment of submission needs a separate execution service, which the $0 budget excludes. Step 4 gives after-the-fact server-side proof at no cost. To run it automatically, create a scheduled GitHub Actions workflow that runs the script with an `ADMIN_TOKEN` secret.

## Speech

- **Listening.** Same design as Vertex, no account and no key. The Worker connects to the free Microsoft Edge "Read Aloud" voice service (`learna/edge-tts.js`) and returns MP3. English uses Ezinne (default) and Abeo, French uses Denise (default) and Henri. French has no Nigerian variant, so `fr-FR` is the right neighbour. Cost and abuse control: every phrase is synthesised once and stored in B2; the browser never sends text (it names course, lesson, step and part, and the server finds the text); each plan has a daily character limit that is returned if synthesis fails.
- **Voice order in the browser.** First that works wins: (1) the same voice built into the browser, if it has it (Microsoft Edge ships all four), which is instant and costs the server nothing; (2) the Worker voice; (3) any device voice, preferring `en-NG`, then `en-GB`, then any English, and for French and other languages the best installed voice for that language. If the device has no voice for the language, the learner is told. After a failure the Worker voice is rested for two minutes; a plan or switch-off answer stops requests until the page is reloaded.
- **Fallback.** Free plan, daily limit, offline, a blocked or slow service, or any error: the device voice is used. Nothing is ever billed.
- **The service is unofficial.** Microsoft can change or block it at any time. When it does, learners hear device voices and nothing else breaks. The connection values in `learna/edge-tts.js` (`EDGE_CHROMIUM`, `EDGE_TTS_TOKEN`) follow the open source `edge-tts` package; update them from its `constants.py` if the service starts refusing connections.
- **Web Audio.** Used for the recording cue sounds and a pace guide for public speaking. Web Audio cannot make speech, so it is not a voice.
- **Per word.** In course text, `[[word]]` shows the word with a small speaker button that pronounces only that word. In language courses every example line has one too.
- **Dictation.** Browser speech recognition (free) where saying beats typing: written answers marked `voice`, and say-it-aloud practice.
- **Honesty about pronunciation.** Say-it-aloud compares what a speech recogniser heard with the target text and says so. It is not an accent or pronunciation score and the screen says that.
- **Recorded tasks.** The server transcribes the recording itself (Whisper), measures pace and filler words from that transcript, and marks the checklist from it. The learner cannot supply measurements.
- **Other languages at $0.** The same path: the Edge neural voice for the language (cached), then the browser voice. Add a voice in `learna/speech.js` `VOICES` (`neural` is the Edge voice id, for example `es-ES-ElviraNeural`) and its name pattern in `NEURAL_NAMES` in `js/learna-speech.js`.

## Tasks, reviews and video

Task formats: text, audio, video, code. `review` is `auto`, `admin` or `both`. Admin-reviewed tasks do not block the course, but a certificate waits for approval. Recordings go to B2 (as Note Taker audio does), are readable only by their owner and staff, and failed automatic attempts keep no recording. Video is practical within limits: 480p at about 0.5 Mbit/s, capped per plan by `learnaVideoSeconds` and `learnaSubmissionMB` (Plus 60 s, 8 MB; Studio 180 s, 20 MB). Video is stored and reviewed by a person. Nothing is inferred from it automatically. `vercel.json` now allows the camera for the app's own pages.

## Certificates

Issued only by the server, from stored progress, the assessment result, task states and reviewer decisions (`learna/certificates.js`). One per learner per course (create-only index document). Each has an unguessable number (`CGN-XXXX-XXXX-XXXX`) and a public check page `certificate.html?id=...` that shows only the name, course and date. Admins can revoke. The name is typed by the learner at claim and cannot be changed afterwards.

## Notifications

Over the existing push subscriptions. Sent only for: a reviewer decision, a certificate ready to claim, and inactivity after real progress (after about 3 days and again after about 10, then nothing until the learner returns). Never daily; at most one every 48 hours and four in 30 days; none from 21:00 to 07:00 in the learner's time zone; each kind can be switched off; no subscription means nothing is sent. The scheduler checks once an hour.

## Admin

Admin screen: `admin.html#courses` and `#reviews`. Admins create, copy, edit, publish, unpublish, revert and delete (never-published only) courses; staff (admin or moderator) review tasks. Edits go to a draft; learners see only the published copy; publishing validates everything first. Enrolled learners keep access to an unpublished course. Every route re-checks the role on the server.

## Adding a course

In the admin Courses screen, or in code: create `learna/courses-<name>.js`, add it to `learna/courses.js`, run `node tests/learna.test.mjs` and `node tests/learna-v2.test.mjs`. New pictures: add a diagram in `scripts/learna-visuals/` and run `python3 scripts/learna-visuals/build.py`.

## Setup for the new features

- Voices need no secrets. Optional Worker variable: `LEARNA_TTS_DISABLED=1` switches the Worker voice off without a deploy (learners then hear device voices). `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` and `LEARNA_TTS_MONTHLY_CAP` are no longer used and can be deleted from the Worker.
- Needs the existing `AI` binding (Whisper), B2 secrets and the `COGNITA_REMINDERS` KV.
- Deploy `vercel.json` (camera permission) with the front end.
- Run `node tests/learna.test.mjs`, `node tests/learna-v2.test.mjs`.
